ABOUT THIS MANUAL
================================================================================

This file exists so that the whole documentation set can be read, searched
and printed as one document. Each section below is the verbatim content of
a README file that also ships in its own module folder, so the two never
disagree: if you prefer to read documentation next to the code, open the
README in the relevant folder instead.

This repository holds the cleaning pipeline: it takes raw Neotree exports
and produces cleaned, validated, dictionary-conformant datasets.
Entry point: cleaning_pipeline_R/run_all.r

Downstream work -- joining admissions to discharges, building master
datasets, and cutting analysis-ready subsamples -- lives in a separate
repository:

  https://github.com/neotree/neotree-sample-maker

The two are loosely coupled: this pipeline writes cleaned datasets to
output/, and the sample maker reads whatever it is given. Neither requires
the other to be present to run.

This manual documents the CODE ONLY -- what each module does and how to run
it. It deliberately contains no Neotree study data, no site-level findings and
no catalogue of data-quality issues; those are maintained separately by the
Neotree team and are not part of this repository.

# Neotree cleaning pipeline

## Purpose

The pipeline cleans raw Neotree data exports for Zimbabwe (`ZIM`) and Malawi (`MWI`). It takes one CSV file per dataset, removes personal data, standardises the columns and values against a data dictionary, assigns a type to every column, validates the values, and writes a cleaned dataset together with reports and a code for every empty cell.

The pipeline is written in R and is made of numbered modules that run in a fixed order. Each input file is processed on its own.

## Folder layout

```
cleaning_pipeline_R/
  run_all.r                  batch runner: every recognised file in input/
  run_pipeline.r             single-file runner: runs the modules in order
  install_packages.r         installs the required CRAN packages
  required_packages.txt      list of the required packages
  readme.md                  this file
  how_to_run.md              run guide

  00_setup/                  settings, shared helpers, configuration list
  00a_pii_detection_removal/ ... 16_na_reason_coding/
                             one folder per module: the script and its README.md
  00_build_dictionary/       scripts that build and check the dictionaries

  dictionaries/              data dictionaries read by the pipeline (.xlsx)
  user_dictionaries/         dictionaries for data users (.xlsx)
  og_dictionaries/           public data dictionary read by the dictionary build
  neotree_data_keys/         data-key exports read by the dictionary build (downloaded)
  neotree_scripts/           Neotree script metadata, zim-scripts/ and mwi-scripts/ (downloaded)
  tests/                     test scripts

  input/                     raw CSV files to clean
  output/                    everything the pipeline writes
```

## Modules

`run_pipeline.r` sources the modules in this order. Every module sources `00_setup/00_setup.r` first, so the settings and the configuration list `cfg` are available to each one.

| Module | Folder | What it does |
|--------|--------|--------------|
| 00 | [`00_setup`](00_setup/README.md) | Loads the libraries, the settings and the dictionary; defines the shared parsers and the personal-data guard; builds `cfg`. |
| 00a | [`00a_pii_detection_removal`](00a_pii_detection_removal/README.md) | Reads the raw CSV, removes columns holding personal data, blanks values that look like personal data, writes the audit report and the completion marker. |
| 01 | [`01_standardise_column_headers`](01_standardise_column_headers/README.md) | Gives every column a standard lower-case name and drops the `.parentKey` columns. |
| 02 | [`02_frame_shift_correction`](02_frame_shift_correction/README.md) | Repairs `uid` values in which another character replaces the hyphen and removes rows with an empty `uid`. |
| 03 | [`03_duplicate_column_merging`](03_duplicate_column_merging/README.md) | Merges columns that share a name into one column. |
| 04 | [`04_dictionary_value_cleaning`](04_dictionary_value_cleaning/README.md) | Rewrites categorical values as the canonical codes of the dictionary where a value matches exactly one code. |
| 05 | [`05_forward_fill_placeholders`](05_forward_fill_placeholders/README.md) | Reads configured fields from their label column into the empty value column (antenatal care visits in Malawi admissions), then copies fixed placeholder words from a label column into its empty value column. |
| 06 | [`06_forward_fill_numeric_datetime`](06_forward_fill_numeric_datetime/README.md) | Fills empty values from the paired label column where the label is a number or a datetime, then drops the paired label columns. |
| 07 | [`07_drop_label_columns`](07_drop_label_columns/README.md) | Drops the remaining label columns and keeps one column per variable prefix. |
| 08 | [`08_drop_autopopulated_columns`](08_drop_autopopulated_columns/README.md) | Passes the data through unchanged and writes a report. |
| 09 | [`09_data_type_assignment`](09_data_type_assignment/README.md) | Converts every column from text to the type given in the dictionary. |
| 10 | [`10_remove_duplicate_rows`](10_remove_duplicate_rows/README.md) | Removes duplicate rows, first per visit and then per patient, keeping the most complete row. With `DEDUP_MODE` set to `"episode"`, admissions and discharges (main and PHC) and the maternal files (Zimbabwe `maternal_outcomes`, Malawi `combined_maternity_outcomes`) keep every row that is not the same record sent again, and gain `baby_id` (and, except the maternal files, `stay_no`). |
| 11 | [`11_numeric_validation`](11_numeric_validation/README.md) | Validates numeric columns, converts weights to grams and applies the dictionary ranges. |
| 12 | [`12_boolean_validation`](12_boolean_validation/README.md) | Sets every boolean column to `TRUE`, `FALSE` or `NA`. |
| 13 | [`13_categorical_object_validation`](13_categorical_object_validation/README.md) | Cleans categorical and free-text columns and turns missing-value text into `NA`. |
| 14 | [`14_datetime_validation`](14_datetime_validation/README.md) | Reads every datetime column as a date-time and sets unrecognised values to `NA`. |
| 14a | [`14a_resolve_neolab_datebct`](14a_resolve_neolab_datebct/README.md) | For the `neolab` dataset, fills missing blood-culture dates from the admissions file, in new columns. |
| 15 | [`15_final_merge_output`](15_final_merge_output/README.md) | Joins the validated columns, strips the column-name suffixes, adds derived columns and writes the cleaned CSV and RDS. |
| 00b | [`00b_rename_harmonised_columns`](00b_rename_harmonised_columns/README.md) | Writes a copy of the cleaned dataset with harmonised column names. Runs only when `SAVE_HARMONISED` is `TRUE`. |
| 16 | [`16_na_reason_coding`](16_na_reason_coding/README.md) | Gives every empty cell of the cleaned dataset a reason code and writes the companion files. |

After the last module, `run_pipeline.r` joins the text reports of the run into one file.

## Input files

Raw CSV files are placed in `input/`. `run_all.r` recognises a file when its name has one of two forms:

```
<country>_<dataset>_<date>.csv
<country>_<source>_<dataset>_<date>.csv
```

| Part | Accepted values |
|------|-----------------|
| `country` | `zim` or `mwi` |
| `source` | `db` or `mb`. Optional. It is recorded in the run plan and does not change how the file is read. |
| `dataset` | `admissions`, `discharges`, `maternal_outcomes`, `phc_admissions`, `phc_discharges`, `combined_maternity_outcomes`, `dhis2_maternal_outcomes`, `maternity_completeness`, `joined_admissions_discharges`, `neolab`, `baseline`, `infections`, `twenty_8_day_follow_up` |
| `date` | `YYYY-MM-DD`, `YYYYMMDD` or `YYYYMMDDHHMM` |

Examples: `zim_admissions_2026-01-31.csv`, `mwi_phc_discharges_2026-01-31.csv`, `mwi_db_admissions_20260131.csv`, `zim_mb_maternal_outcomes_202601311030.csv`.

A file whose name has neither form, or whose dataset is not in the list, is listed as skipped and the other files are still processed.

The pipeline reads exports with database-style headers (`unique_key`) and with Metabase-style headers (`Unique Key`), and values in either style or a mixture. `00_setup.r` detects the style of each file and records it in the log; the style does not change how the file is parsed.

## Outputs

Everything written for one input file goes to `output/<file stem>/`, where `<file stem>` is the input file name without `.csv`.

| File | Content | Written |
|------|---------|---------|
| `<file stem>_cleaned.csv` | Cleaned dataset. Date-times as `YYYY-MM-DD HH:MM:SS` (UTC); `NA` as an empty field. | Always |
| `<file stem>_cleaned.rds` | Cleaned dataset with typed columns. | Always |
| `<file stem>_cleaned_na_coded.csv` | Cleaned dataset, every column as text, with each empty cell replaced by its reason code. | When `SAVE_NA_CODED` is `TRUE` (default) |
| `<file stem>_cleaned_na_reasons.csv.gz` | Same rows and columns as the cleaned dataset; each cell holds the reason code where the cleaned cell is empty. | When Module 16 runs |
| `<file stem>_cleaned_na_reasons_summary.csv` | One row per variable: number of rows, values present and missing, and cells per reason code. | When Module 16 runs |
| `<file stem>_cleaned_na_reasons_long.csv.gz` | One row per coded cell, with the raw value. | When `SAVE_NA_REASONS_LONG` is `TRUE` |
| `<file stem>_cleaned_harmonised.csv`, `.rds` | Cleaned dataset with harmonised column names. | When `SAVE_HARMONISED` is `TRUE` |
| `<file stem>_cleaned_stage1.rds` | Data frame after duplicate-row removal. | When `SAVE_STAGE1_CHECKPOINT` is `TRUE` |
| `<file stem>_episode_keys.rds` | Admission records with their `baby_id` and `stay_no`, read by the discharges run. Holds `uid` values. | Admissions, when `DEDUP_MODE` is `"episode"` |
| `<file stem>_deidentified.csv` | Raw data after removal of personal data, before any cleaning. | When `SAVE_DEIDENTIFIED` is `TRUE` |
| `<file stem>.log` | Run log. Messages are appended. | Always |
| `00a_pii_removal_complete.dcf` | Completion marker of Module 00a. | Always |
| `reports/` | One text report per module, and `00_pipeline_report.txt`, which joins them. | Unless reports are suppressed |

The reason codes are:

| Code | Meaning |
|------|---------|
| `-6` | Redacted: the raw value matches a personal-data value pattern. |
| `-7` | Not applicable: the skip condition of the field in the Neotree script is false for the record. |
| `-8` | Invalid or removed: the raw cell held a value and the cleaned cell is empty. |
| `-9` | Unknown: every other empty cell. |

Module 16 runs when the folder `neotree_scripts/` exists. Otherwise a warning is logged and the NA-reason and NA-coded files are not written.

## Data keys and script metadata

The dictionary build reads the data-key exports in `neotree_data_keys/`, and the build and Module 16 read the script metadata in `neotree_scripts/`. Both are downloaded from the Neotree web editors, https://webeditor.neotree.org/ and https://zim-webeditor.neotree.org:10243/, with a Neotree account. They contain the names of health workers and are not part of the published repository. The README file in each folder lists the files and where they go.

## Dictionaries

The pipeline reads one workbook per country and dataset, `dictionaries/dictionary_<country>_<dataset>.xlsx`. The dictionary determines how each column is treated:

| Sheet | Used for |
|-------|----------|
| `Variables` | The type of each variable (`numeric`, `boolean`, `categorical`, `datetime`, `object`), whether it is used in analysis, whether it is confidential, which weights are in grams, the lower and upper limits of numeric variables, and the harmonised name. |
| `ValueMaps` | The raw codes, option labels and canonical codes of each categorical variable. |
| `PII_Patterns` | Column-name patterns that mark personal data. |

When a dataset has no workbook of its own, the workbook of a related dataset is used where a fallback is defined in `00_setup.r`. A column of the input file that the dictionary does not cover passes through as text: it is not typed or validated. Such columns are reported on the console, in the log and in `00c_undocumented_columns.txt` in the report folder.

The workbooks are generated by the scripts in `00_build_dictionary/` and are replaced by a rebuild. Their sheets and columns are described in [`dictionaries/README.md`](dictionaries/README.md); the build is described in [`00_build_dictionary/README.md`](00_build_dictionary/README.md). The `_enriched.xlsx` workbooks and the workbooks in `user_dictionaries/` are documentation and are not read by the cleaning modules.

## Personal data

Module 00a is the only module that reads the raw CSV in full, and it runs before any cleaning. It applies three rules:

| Rule | Action |
|------|--------|
| Tier 1 | Removes the value and label columns of every variable flagged `confidential` in the dictionary. |
| Tier 2 | Removes every column whose name matches a pattern of the `PII_Patterns` sheet or a built-in pattern in `00_setup.r`. |
| Tier 3 | Sets to `NA` every value that matches a value pattern: phone numbers, e-mail addresses, a three-part number pattern and two national identity number shapes. |

The key and system columns (`uid`, `facility`, `uniquekey`, the timestamp columns, `scriptversion`, `scriptid`) are tested by Tier 3 but never changed; a match is reported. Columns that match a quasi-identifier pattern, such as a village or district, are kept and listed in the audit report. The audit report, `reports/00a_pii_audit_report.txt`, holds column names and counts only.

### Guard

When Module 00a finishes, it writes the completion marker `00a_pii_removal_complete.dcf` in the run folder and attaches a run id to the data frame. The marker records the input file (path, size, modification time) and the checksum of the dictionary. Any marker left by an earlier run is deleted when Module 00a starts.

The function `assert_pii_removed()` in `00_setup.r` stops the run unless:

1. the marker exists and is complete;
2. the marker describes the current input file and dictionary;
3. no column belongs to a confidential variable or matches a column-name pattern;
4. no value outside the exempt columns matches a value pattern.

Module 01 stops if the de-identified data frame does not exist, and calls the guard with an extra check that the data frame carries the run id in the marker. The guard is called again before each write of row-level data: the removed rows of Module 02, the checkpoint of Module 10, the cleaned outputs of Module 15, the harmonised outputs of Module 00b and each table of Module 16. If a check fails, the file is not written. Messages from the guard give column names, pattern names and counts, never values.

## Derived columns

The pipeline adds these columns to the cleaned dataset. The columns they are derived from are not changed.

| Column | Added by | Content |
|--------|----------|---------|
| `mat_age_date_years` | Module 11 | `matagedate` (maternal age in hours) converted to whole years. Added when `matagedate` is present. |
| `hepbdate_date` | Module 14 | The values of `hepbdate` that are dates. Added when `hepbdate` is present and is not itself a datetime column. |
| `datebct_resolved` | Module 14a | `datebct` where present, otherwise the admission date-time of the same patient. `neolab` dataset only. |
| `datebct_source` | Module 14a | `"original"`, `"from_admission"` or `NA`. `neolab` dataset only. |
| `birthweight_g` | Module 15 | First non-missing of `birthweight`, `bwt`, `bwtdis`, in grams. |
| `admission_weight_g` | Module 15 | `admissionweight` in grams. Added when `admissionweight` is present. |
| `discharge_weight_g` | Module 15 | `dischweight` in grams. Added when `dischweight` is present. |
| `mat_age_years_combined` | Module 15 | `matageyrs` where present, otherwise `mat_age_date_years`. Added when either is present. |
| `mat_age_source` | Module 15 | `"matageyrs"`, `"matagedate_derived"` or `"none"`. |
| `antenatalcare_source` | Module 05 | `"raw_numeric_value"`, `"raw_exact_label"`, `"raw_range_label"` or `"unresolved"`. Malawi `admissions` only. |
| `antenatalcare_category` | Module 15 | `"none"`, `"1_3"`, `"ge4"` or `NA`. Malawi `admissions` only. |

In the cleaned dataset the suffixes `.value` and `.valuedischarge` are removed from all column names.

# How to run the Neotree cleaning pipeline

This guide covers installation, input files, the two runners, the settings, the outputs, the dictionary rebuild and the tests. What each module does is described in [`readme.md`](readme.md) and in the `README.md` of each module folder.

All commands are given from the pipeline folder, `cleaning_pipeline_R/`. The runners set the working directory to their own folder when they start, so they can be launched from any directory.

## Requirements

- R.
- Twelve CRAN packages: `jsonlite`, `readr`, `readxl`, `writexl`, `dplyr`, `tidyr`, `stringr`, `lubridate`, `purrr`, `logger`, `janitor`, `tibble`. `required_packages.txt` lists them with their minimum versions.
- `openxlsx`, for the dictionary scripts other than `00_build_dictionary.r`. `install_packages.r` does not install it.

### Installing the packages

```
Rscript install_packages.r
```

or, in an R session:

```r
source("install_packages.r")
```

The script installs the missing packages with their dependencies from `https://cloud.r-project.org`, then loads each required package and prints `[OK]` or `[FAIL]` for it. If a package fails to load, the script prints the `install.packages()` call to run by hand.

## Input files

Place the raw CSV files in `input/`. `run_all.r` processes a file when its name has one of these forms:

```
<country>_<dataset>_<date>.csv
<country>_<source>_<dataset>_<date>.csv
```

| Part | Accepted values |
|------|-----------------|
| `country` | `zim` or `mwi` |
| `source` | `db` or `mb`. Optional; it does not change how the file is read. |
| `dataset` | `admissions`, `discharges`, `maternal_outcomes`, `phc_admissions`, `phc_discharges`, `combined_maternity_outcomes`, `dhis2_maternal_outcomes`, `maternity_completeness`, `joined_admissions_discharges`, `neolab`, `baseline`, `infections`, `twenty_8_day_follow_up` |
| `date` | `YYYY-MM-DD`, `YYYYMMDD` or `YYYYMMDDHHMM` |

Examples:

```
zim_admissions_2026-01-31.csv
zim_discharges_2026-01-31.csv
mwi_phc_admissions_2026-01-31.csv
mwi_db_neolab_20260131.csv
zim_mb_maternal_outcomes_202601311030.csv
```

The file extension is `.csv` in lower case.

Two modules read a second file from the same folder as the input file:

| Module | Second file | Found by |
|--------|-------------|----------|
| 02 | The other half of an admissions/discharges pair (`admissions` with `discharges`, `phc_admissions` with `phc_discharges`). | The input file name with the dataset swapped; if that file is absent, the last file in sorted order named `<country>_[db_\|mb_]<paired dataset>_<date>.csv`. |
| 14a | The admissions file, when the dataset is `neolab`. | The input file name with `neolab` replaced by `admissions`. |

Both modules run without the second file. Module 02 then gives its repairs the status `unchecked`, and Module 14a leaves missing dates unresolved.

Each dataset needs a dictionary, `dictionaries/dictionary_<country>_<dataset>.xlsx`, or a fallback defined in `00_setup.r` (see [`00_setup/README.md`](00_setup/README.md)).

## Running a batch: `run_all.r`

```
Rscript run_all.r
```

or, in an R session:

```r
source("run_all.r")
```

`run_all.r` does the following.

1. Lists the `.csv` files in `input/` and applies the two filters below.
2. Reads the country, source and dataset from each file name. A file is skipped when its name has neither accepted form (`filename does not match expected pattern`) or when its dataset is not in the list (`unrecognised dataset type '<dataset>' (not in KNOWN_DATASETS)`).
3. Prints the run plan: the files to process and the files skipped, with the reason.
4. For each file, sets `COUNTRY`, `DATASET`, `DATA_SOURCE` and `CSV_FILEPATH`, sets `DICT_FILEPATH`, `OUTPUT_CSV`, `OUTPUT_RDS`, `REPORT_DIR` and `NEOTREE_SCRIPTS_DIR` to `NULL` and `OUTPUT_DIR` to `"output"`, and sources `run_pipeline.r`.
5. If a file fails, records the error message and continues with the next file.
6. Removes the objects of the run from the global environment before the next file.
7. Prints the batch summary: the number of files that succeeded and failed, the total time, each failed file with its error message, and each file that succeeded with its country, detected export style and dataset.

### Batch filters

Both are set near the top of `run_all.r`.

| Setting | Default | Effect |
|---------|---------|--------|
| `RUN_ALL_FILTER` | `NULL` | A regular expression applied to the file name. Only matching files are kept. `NULL` keeps every file. Example: `"^zim_"`, or `"admissions\|discharges"`. |
| `RUN_ALL_SKIP` | `character(0)` | File names to leave out, written in full. |

## Running one file: `run_pipeline.r`

`run_pipeline.r` runs the modules in order for the file named in `CSV_FILEPATH`. The settings are defined in the user configuration block of `00_setup/00_setup.r`. Each one is assigned only if it does not already exist, so there are two ways to set them.

Edit the defaults in `00_setup/00_setup.r`, then:

```
Rscript run_pipeline.r
```

Or set them in an R session before sourcing the runner:

```r
COUNTRY      <- "ZIM"
DATASET      <- "admissions"
CSV_FILEPATH <- "input/zim_admissions_2026-01-31.csv"
source("run_pipeline.r")
```

A setting defined in the session keeps its value for later runs in that session. This includes the paths that `00_setup.r` resolves when they are `NULL`. Before running a second file in the same session, set `DICT_FILEPATH`, `OUTPUT_CSV`, `OUTPUT_RDS`, `REPORT_DIR` and `NEOTREE_SCRIPTS_DIR` back to `NULL` and remove `SKIP_DEDUP_STAGE2` and `DEDUP_MODE`, as `run_all.r` does, or start a new session.

When it finishes, `run_pipeline.r` prints the time taken, the paths of the cleaned CSV and RDS, the number of rows and columns, and the report folder.

## Settings

All settings below are in the user configuration block of `00_setup/00_setup.r`.

### Identity and paths

| Setting | Default | Effect |
|---------|---------|--------|
| `COUNTRY` | `"ZIM"` | `"ZIM"` or `"MWI"`. |
| `DATASET` | `"admissions"` | One of the datasets listed under *Input files*. |
| `DATA_SOURCE` | `"auto"` | Accepts `auto`, `database`, `metabase`, `mixed` or `unknown`. It does not change how the file is parsed and is replaced by the export style detected from the file. |
| `CSV_FILEPATH` | a file in `input/` | Path of the raw CSV. |
| `DICT_FILEPATH` | `NULL` | Path of the dictionary. `NULL` gives `dictionaries/dictionary_<country>_<dataset>.xlsx`, or the fallback dictionary when that file does not exist. |
| `OUTPUT_DIR` | `"output"` | Base folder for everything the pipeline writes. The run folder is `<OUTPUT_DIR>/<file stem>/`. |
| `OUTPUT_CSV`, `OUTPUT_RDS` | `NULL` | Paths of the cleaned outputs. `NULL` gives `<file stem>_cleaned.csv` and `<file stem>_cleaned.rds` in the run folder. |
| `REPORT_DIR` | `NULL` | `NULL` gives `reports/` in the run folder. A path writes the reports there. `FALSE` or `""` suppresses the module reports. |

### Module behaviour

| Setting | Default | Effect |
|---------|---------|--------|
| `SKIP_DEDUP_STAGE2` | `TRUE` when the dataset is `infections` or `neolab`, otherwise `FALSE` | `TRUE` makes Module 10 skip its patient-level stage, so several rows per patient are kept. Module 15 then keeps one row per `uid`, `facility` and `uniquekey` instead of one per `uid` and `facility`. |
| `DEDUP_MODE` | `"episode"` | Stage 2 of Module 10 for `admissions`, `discharges`, `phc_admissions`, `phc_discharges`, Zimbabwe `maternal_outcomes` and Malawi `combined_maternity_outcomes`. `"current"` keeps one row per `uid` and `facility`. `"episode"` collapses rows only when they are the same record sent more than once, keeps every other row and adds `baby_id`, `stay_no` (not in the maternal files) and flag columns (see the [Module 10 README](10_remove_duplicate_rows/README.md)); Modules 11 to 16 then key rows on `uid`, `facility` and `uniquekey`. ### Settings in a batch

`run_all.r` sets the identity and path settings for each file as described above. It removes the output flags, `SKIP_DEDUP_STAGE2`, `UID_REPAIR_SEPARATORS`, `RESERVED_COLUMN_RENAMES` and `LABEL_VALUE_RULES` from the global environment after each file, so for a batch these are changed by editing their defaults in `00_setup/00_setup.r`. The exception is `DEDUP_MODE`, which `run_all.r` sets for every file from `RUN_ALL_DEDUP_MODE`, near the top of the script (default `"episode"`). Files run in name order, so an admissions file runs before the discharges file of the same country and source.

# Dictionary build scripts

## Purpose

The scripts in this folder build the data dictionaries that the cleaning pipeline reads, add documentation columns to them, build the dictionaries for data users, and check the result.

## Scripts and order

| Step | Script | Writes | Described in |
|------|--------|--------|--------------|
| 1 | `00_build_dictionary.r` | `dictionaries/dictionary_<country>_<dataset>.xlsx` | this file |
| 2 | `00c_enrich_dictionary_from_scripts.r` | `dictionaries/dictionary_<country>_<dataset>_enriched.xlsx` | `README_enrich_from_scripts.md` |
| 3 | `00e_enrich_from_public_dictionary.r` | adds columns to the `_enriched.xlsx` workbooks | `README_enrich_from_public.md` |
| 4 | `00d_build_user_dictionary.r` | `user_dictionaries/neotree_user_dict_<country>.xlsx` | `README_user_dictionary.md` |
| 5 | `validate_dictionaries.r` | console report | this file |

The sheets and columns of the dictionary workbooks are described in `dictionaries/README.md`.

Running `00_build_dictionary.r` runs steps 1 to 4 in order, removes staff names (see below) and checks the result; step 5 is run separately. With `RUN_FOLLOW_ON_STEPS` set to `FALSE` the script builds the base dictionaries only, and does not remove staff names.

Step 1 is required before the cleaning pipeline can run. Steps 2 to 4 produce documentation and are not read by the cleaning pipeline. Step 3 must follow step 2, because step 2 starts again from the base workbook and replaces the `_enriched.xlsx` copy.

The data keys and the script metadata are downloaded from the Neotree web editors with a Neotree account; see `neotree_data_keys/README.md` and `neotree_scripts/README.md`. They are not part of the published repository.

## When to run it

Run `00_build_dictionary.r` when:

- a new data-key export is placed in `neotree_data_keys/downloaded/`;
- a constant in `00_build_dictionary.r` or a row of `user_ranges.xlsx` is changed;
- new Neotree script files are placed in `neotree_scripts/`.

## `00_build_dictionary.r`

### What it does

The script builds one workbook for each country and dataset listed in `BUILD_PLAN`. If one combination fails, the error is printed and the others are still built. For each combination, `build_dictionary()` does the following.

1. **Selects the keys of the dataset.** A data key belongs to the dataset when it is used by a script whose title matches the regular expression of the dataset in `DATASET_FILTERS` (case is ignored). Deleted keys and option entries are left out.
2. **Keeps one row per variable.** `question_key` is the key name in lower case with everything except letters and digits removed. When several keys give the same `question_key`, the one with the latest publish date is kept. An entry in `KEY_UUID_OVERRIDES` names the key to keep instead, for one country, dataset and `question_key`.
3. **Fills the `Variables` columns.** `r_type` comes from `PIPELINE_TYPE_MAP`. `use_in_analysis` is `FALSE` for free-text keys, summary-table keys and draft keys. `weight_unit` is `grams` for the keys in `WEIGHT_KEYS_GRAMS`. The record-level system keys in `RECORD_ID_KEYS` receive a `record_id_role`; `uid` and `facility` receive a `linkage_role`.
4. **Adds legacy variables.** Each entry of `LEGACY_VARIABLES` for the country and dataset is added as a row, unless the `question_key` is already present. These are fields that occur in the data but not in the data-key export.
5. **Adds derived variables.** Each entry of `DERIVED_VARIABLES` for the country and dataset is added as a row, unless already present. These are columns computed by the cleaning pipeline. Their `raw_value_column` and `raw_label_column` are empty and their `raw_data_type` is `derived`.
6. **Applies `MANUAL_RANGES`.** For each listed `question_key`, the lower and upper limits are filled where they are still empty.
7. **Applies `user_ranges.xlsx`.** See below. These limits replace any limit set so far.
8. **Assigns PII tiers.** `pii_tier` is `1` where `confidential` is `TRUE`. Each pattern of `PII_PATTERNS_DATA` is then tested against `question_key`; a match on a variable without a tier gives tier `2`, with the category and the pattern recorded. Each pattern of `QUASI_ID_PATTERNS` is tested in the same way and gives `quasi` to a variable still without a tier.
9. **Builds `ValueMaps`.** The options of the kept key are listed in order, with `canonical_code` equal to `raw_code`. Leading and trailing spaces are removed from codes and labels. Each label is kept once per variable. Options that exist in other non-deleted versions of the same key, and whose code and label are both absent so far, are appended after them.
10. **Applies `VARIABLE_PATCHES`.** Each entry sets the named columns of one variable in the listed datasets of one country.
11. **Applies `VALUEMAP_PATCHES`.** Each entry carries one action on one variable:

    | Action | Effect |
    |--------|--------|
    | `add_rows` | Appends the given options. An option whose label already exists for the variable is not added. |
    | `update_canonical` | Sets `canonical_code` for the given `raw_code` values. |
    | `remove_duplicate_raw_code` | Where a `raw_code` has several rows, keeps the row with the given label and removes the others. |

    A patch for a variable or code that is not present is skipped.
12. **Builds `ReviewNeeded`.** Lists categorical variables with no row in `ValueMaps`, numeric variables with no limits, and variables with no `r_type`.
13. **Writes the workbook** with the sheets `Variables`, `ValueMaps`, `PII_Patterns` and `ReviewNeeded`.

### Staff names

Some answer options in the data keys and the scripts are the names or codes of health workers, and some script titles contain names. No dictionary receives them:

1. **Script titles.** Each title listed in `00_build_dictionary/private/script_title_replacements.tsv` (columns `original_title` and `published_title`) is replaced as soon as the data keys are read. The `private/` folder is not part of the published repository.
2. **Answer options of staff fields.** The fields are the keys matched by `STAFF_KEY_PATTERN` in `staff_fields.r`. Their options are not written to `ValueMaps`, and their `Values / Codes` cell in the user dictionaries reads `Not listed (staff identifier)`. `00d_build_user_dictionary.r` reads the same file.
3. **Other text.** The answer options of staff fields in the data keys and the scripts are collected. Any of them still found in a cell of a dictionary is replaced by `[staff]`. Names of two or more words are matched in any letter case; single words and codes only in their exact case. Header rows are not changed, and a string that is also used outside staff fields, such as `Other` or a word that occurs in a question, is left as it is.
4. **Check.** Every workbook file in `dictionaries/` and `user_dictionaries/` is then read in full, including text kept in the file but shown in no cell. The run stops with an error, naming the files and the number of matches, if a staff name, a staff code or a listed title is found.

### Functions

`load_country_keys(country)` reads the two export files of a country and returns a list with `metadata`, `usage` and `opt_lookup`.

`build_dictionary(country, dataset, out_path = NULL, include_review = TRUE, keys = NULL)` writes one workbook and returns, invisibly, a list with `variables`, `value_maps` and `review_needed`. With `out_path = NULL` the file is named `dictionary_<country>_<dataset>.xlsx` in `dictionaries/`. With `include_review = FALSE` the `ReviewNeeded` sheet is left out.

## `validate_dictionaries.r`

Checks the base workbooks in `dictionaries/` and prints `[OK]`, `[WARN]` or `[FAIL]` for each check, then a summary. It changes no file.

The six workbooks for `admissions`, `discharges` and `maternal_outcomes` of both countries must exist. The other workbooks are checked when present.

| Check | Result if not met |
|-------|-------------------|
| The sheets `Variables`, `ValueMaps`, `PII_Patterns` and `ReviewNeeded` exist | fail |
| `Variables`, `ValueMaps` and `PII_Patterns` have all their columns | fail |
| `PII_Patterns` has at least one row and no blank pattern | fail |
| `PII_Patterns` has no repeated pattern | warning |
| Every variable with `use_in_analysis` `TRUE` has an `r_type` | warning |
| Every `question_key` in `ValueMaps` exists in `Variables` | warning |
| Where both limits are set, the lower is below the upper | fail |
| `pii_tier` is `1`, `2`, `quasi` or empty | fail |
| Every tier 2 variable has a `pii_matching_pattern` | warning |
| Every variable with `confidential` `TRUE` has tier `1` or `2` | warning |
| In the Zimbabwe admissions workbook, the Apgar, oxygen saturation and Thompson score limits equal those of `EXPECTED_RANGES_ZIM_ADM` | warning |

For each workbook it also prints the number of variables, value-map rows and review items, and the number of variables per `r_type` and per `pii_tier`.

When run with `Rscript`, the exit status is 1 if any check failed and 0 otherwise.

## How to run it

Each script finds the pipeline folder from its own location, so it can be started from any working directory. One command runs steps 1 to 4, the removal of staff names and the check:

```r
source("00_build_dictionary/00_build_dictionary.r")
```

The validation is run afterwards:

```r
source("00_build_dictionary/validate_dictionaries.r")
```

or, from a terminal:

```
Rscript 00_build_dictionary/00_build_dictionary.r
```

Packages used: `jsonlite`, `readxl`, `dplyr`, `tidyr`, `stringr`, `writexl`, `tibble`, `janitor`, `purrr`, `logger` (build); `jsonlite`, `openxlsx`, `readxl` (steps 2 to 4); `openxlsx` (validation).

# `00c_enrich_dictionary_from_scripts.r`

## Purpose

Adds four columns to the `Variables` sheet of each dictionary workbook, taken from the Neotree script files: the label shown in the app, whether the field is optional, its skip condition, and a comparison of its options with the `ValueMaps` sheet.

## When to run it

After `00_build_dictionary.r` and before `00e_enrich_from_public_dictionary.r`. Run it again when the dictionaries are rebuilt or when the files in `neotree_scripts/` change.

## What it does

For each base workbook `dictionaries/dictionary_<country>_<dataset>.xlsx` (files ending in `_enriched.xlsx` are not taken as input):

1. **Reads the country and dataset from the file name.**
2. **Chooses the scripts of the dataset.** These are the entries of `FACILITY_SCRIPT_MAP` for the country and dataset. `normalise_dataset_name()` first maps `combined_maternity_outcomes`, `dhis2_maternal_outcomes` and `maternity_completeness` to `maternal_outcomes`, and `infections` to `neolab`. For a dataset whose name contains `phc`, the scripts of the country whose title contains `PHC` or `primary ... health`, and `admis` or `disch` as appropriate, are added. If no script is chosen, or none of the chosen scripts is found among the files, the workbook is skipped and no output is written for it.
3. **Reads the fields of those scripts.** For every field on every screen it takes the key, the label, the `optional` flag, the options, and the condition. The condition is the field condition, or the screen condition if the field has none, or `(screen condition) AND (field condition)` if both exist and differ. Keys are put in lower case.
4. **Summarises each key across the scripts.**

   | Column | Value |
   |--------|-------|
   | `display_label` | The most frequent non-empty label. |
   | `optional` | The flag, if all scripts that state it agree; otherwise empty. |
   | `skip_condition` | The most frequent non-empty condition; empty if there is none. |
   | `valuemap_check` | Compares the option codes of the most frequent option list with the `raw_code` values of the variable in `ValueMaps`. `TRUE` if the two sets differ or the variable has no row in `ValueMaps`; `FALSE` if they are the same; empty if the field has no options in the scripts. |

5. **Writes the four columns** into the `Variables` sheet, matching on `question_key`. Existing columns of the sheet are not changed. A variable that is not found in the scripts keeps empty cells in the four columns. If the columns already exist they are refreshed in place; otherwise they are appended after the last column.
6. **Saves the workbook.**

## Inputs

| File | Description |
|------|-------------|
| `dictionaries/dictionary_<country>_<dataset>.xlsx` | Base workbooks from `00_build_dictionary.r` |
| `neotree_scripts/zim-scripts/*.json`, `neotree_scripts/mwi-scripts/*.json` | Neotree script files |

The script stops if `dictionaries/` or `neotree_scripts/` does not exist, if no script file is found, or if there is no base workbook.

## Outputs

| File | Description |
|------|-------------|
| `dictionaries/dictionary_<country>_<dataset>_enriched.xlsx` | Copy of the base workbook with the four columns. An existing file is replaced. |

The columns are described in `dictionaries/README.md`. Progress is printed on the console with the prefix `[00c]`: for each workbook, the number of scripts matched, the number of variables filled, and the number of variables with `valuemap_check` `TRUE`.

## Configuration

Set at the top of the script.

| Setting | Default | Effect |
|---------|---------|--------|
| `OVERWRITE_IN_PLACE` | `FALSE` | `FALSE` writes `_enriched.xlsx` copies. `TRUE` writes the columns into the base workbooks. |
| `NEOTREE_SCRIPTS_BASE` | `neotree_scripts` | Folder holding `zim-scripts/` and `mwi-scripts/`. |
| `DICT_DIR` | `dictionaries` | Folder of the dictionary workbooks. |

`FACILITY_SCRIPT_MAP` lists the script identifiers per country, dataset and facility. The same kind of map exists in `00d_build_user_dictionary.r` and in `16_na_reason_coding/helpers/03_facility_script_map.r`; each script reads its own.

## How to run it

```r
source("00_build_dictionary/00c_enrich_dictionary_from_scripts.r")
```

or `Rscript 00_build_dictionary/00c_enrich_dictionary_from_scripts.r`. Packages used: `jsonlite`, `openxlsx`.

# `00e_enrich_from_public_dictionary.r`

## Purpose

Adds eight documentation columns to the `Variables` sheet of each dictionary workbook, taken from the public data dictionary in `og_dictionaries/`. It does not change `ValueMaps`, codes, limits or any other existing column.

## When to run it

After `00c_enrich_dictionary_from_scripts.r`. Run it again when the dictionaries are rebuilt, when `00c` is run again, or when the public data dictionary file is replaced.

## What it does

1. **Reads the public data dictionary.** The sheets named in `PUBLIC_SHEETS` are read without a header row. A row with a value in the third column starts a variable; from that row the script takes the variable name (column 3), meaning (4), data type (7), dependency (8), range (9), old variable name (10), timeline of change (11) and reference (13). Rows below it with an empty third column are option rows and are not used. A sheet that cannot be read is skipped.
2. **Builds one index for all sheets.** Each entry is indexed by its variable name and by its old variable name, in lower case. When a name occurs more than once, the first entry is kept.
3. **Fills each workbook.** Each output is built from the base workbook in `dictionaries/`. The four columns written by `00c_enrich_dictionary_from_scripts.r` are carried over from an existing `_enriched.xlsx` copy only when that copy is not older than the base workbook and lists the same variables in the same order; otherwise they are left out and a message says so. Each variable is looked up by `question_key` and, if that is not found, by `harmonised_variable_name`.

   | Column | Value |
   |--------|-------|
   | `public_meaning` | Meaning |
   | `public_data_type` | Data type |
   | `public_dependency` | Dependency |
   | `public_range` | Range |
   | `old_variable_name` | Old variable name, if it differs from the current name |
   | `timeline_of_change` | Timeline of change |
   | `public_reference` | Reference |
   | `public_dict_matched` | `TRUE` if an entry was found, `FALSE` otherwise |

   For a variable with no entry, the seven text columns are empty.
4. **Writes the eight columns** into the `Variables` sheet. If they already exist they are refreshed in place; otherwise they are appended after the last column. A workbook with no `Variables` sheet, or an empty one, is skipped.
5. **Saves the workbook.**

## Inputs

| File | Description |
|------|-------------|
| `og_dictionaries/Public_data_dictionary_2024.xlsx` | Public data dictionary. The script stops if it is missing. |
| `dictionaries/dictionary_<country>_<dataset>_enriched.xlsx` | Source of the four `00c` columns, where it exists and matches the base workbook |
| `dictionaries/dictionary_<country>_<dataset>.xlsx` | Source otherwise. The script stops if there is no base workbook. |

## Outputs

| File | Description |
|------|-------------|
| `dictionaries/dictionary_<country>_<dataset>_enriched.xlsx` | The base workbook with the `00c` columns carried over and the eight columns. An existing file is replaced. |

The columns are described in `dictionaries/README.md`. For each workbook the console shows the number of variables matched, with the prefix `[00e]`.

## Configuration

Set at the top of the script.

| Setting | Default | Effect |
|---------|---------|--------|
| `OVERWRITE_IN_PLACE` | `FALSE` | `FALSE` reads the base workbooks and writes the `_enriched.xlsx` copies. `TRUE` reads the base workbooks and writes the columns into them. |
| `DICT_DIR` | `dictionaries` | Folder of the dictionary workbooks. |
| `PUBLIC_DICT` | `og_dictionaries/Public_data_dictionary_2024.xlsx` | Path of the public data dictionary. |
| `PUBLIC_SHEETS` | seven sheet names | Sheets of the public data dictionary that are read. |

## How to run it

```r
source("00_build_dictionary/00e_enrich_from_public_dictionary.r")
```

or `Rscript 00_build_dictionary/00e_enrich_from_public_dictionary.r`. Packages used: `readxl`, `openxlsx`.

# `00d_build_user_dictionary.r`

## Purpose

Builds the user dictionary: one Excel workbook per country that lists, for each dataset, the variables of the cleaned data in the order of the Neotree form, with their description, type, values and missing-value codes. It is a reference for people who use the cleaned data. The cleaning pipeline does not read it.

## When to run it

After `00_build_dictionary.r`, `00c_enrich_dictionary_from_scripts.r` and `00e_enrich_from_public_dictionary.r`. Run it again when the dictionaries are rebuilt or when the files in `neotree_scripts/` change.

## What it does

For each country (`ZIM`, `MWI`) and each dataset in `DATASET_CONFIGS`:

1. **Chooses the scripts of the dataset.** These are the entries of `FACILITY_SCRIPT_MAP` for the country and dataset; `infections` uses the entry for `neolab`. For the two PHC datasets, if the map has no entry, the scripts of the country whose title contains one of the keywords in `PHC_ADMISSION_KW` or `PHC_DISCHARGE_KW` are used. Identifiers with no file in `neotree_scripts/` are dropped. A dataset with no script gets no sheet.
2. **Reads the fields of those scripts** in screen and field order, with keys in lower case, and keeps one row per key:

   | Item | Taken from |
   |------|------------|
   | Section | The most frequent screen title of the key |
   | Position | The lowest screen number with that title, then the lowest field number |
   | Label | The first non-empty label |
   | Skip condition | The first non-empty condition (screen and field conditions joined with `AND` when both exist and differ) |
   | Options | The longest option list |

3. **Reads the dictionary workbook of the dataset**: the `_enriched.xlsx` copy if it exists and `USE_ENRICHED_DICT` is `TRUE`, otherwise the base workbook. Variables are matched on `question_key`.
4. **Leaves out** every variable whose `pii_tier` is `1` or whose `use_in_analysis` is `FALSE`. A field that is in the scripts but not in the dictionary is kept, with an empty type.
5. **Adds the derived variables.** Each key in `DERIVED_KEYS` that is in the dictionary of the dataset, and not left out by step 4, is added in the section `Derived variables (computed by the cleaning pipeline)`.
6. **Writes one sheet per dataset**, then a `Master` sheet.

### Columns of a dataset sheet

| Column | Content |
|--------|---------|
| `Description` | `display_label` of the dictionary; if empty, the label in the scripts; if empty, `variable_label`; if empty, the key. For derived variables, `variable_label`. |
| `Variable Name` | `harmonised_variable_name`; if empty, the key. |
| `Type` | `Numeric`, `Boolean`, `Categorical`, `Text` or `Date/time`, from `r_type`. |
| `Values / Codes` | See below. |
| `NA Codes` | The missing-value codes that can occur for the variable. See below. |
| `Available also in` | The other datasets of the same country that contain the variable. |

`Values / Codes` (for a staff field, see `staff_fields.r`, it reads `Not listed (staff identifier)`):

| Type | Content |
|------|---------|
| Numeric | `Range: a to b`, `Range: >= a` or `Range: <= b` from the limits in the dictionary; `Numeric value` if there are none. |
| Date/time | `Date / time value` |
| Text | `Free text` |
| Boolean, Categorical, or no type | One line `code = label` per option, from the `ValueMaps` sheet in `option_order`, using `raw_code` and the first label of each code. If the variable has no row there, the options in the scripts. If there are none, `true / false` for a Boolean and empty otherwise. |
| Derived variables | Empty |

`NA Codes`:

| Code | Listed when |
|------|-------------|
| `-9` | Always |
| `-8` | The type is Numeric, Boolean, Categorical or Date/time |
| `-7` | The variable has a skip condition (`skip_condition` of the dictionary, or the condition in the scripts) |
| `-6` | The type is Text and `pii_tier` is set and is not `1` |

### Layout of a dataset sheet

The first row is the header and is frozen. Variables are grouped under section rows:

1. `Administrative / System`: variables with a `record_id_role` or a `linkage_role` in the dictionary.
2. One section per screen title, in form order.
3. `Derived variables (computed by the cleaning pipeline)`.
4. `Other`, for fields whose screen has no title.

### Sheets of the workbook

| Sheet | Content |
|-------|---------|
| `About` | Title, date of generation and a short description of the workbook. |
| `NA Codes` | The four numeric codes `-6` to `-9` with their meaning and priority, a list of text codes entered by data collectors in the raw data, and a note on how the two kinds are used. |
| One per dataset | As above. The sheet is named with the `sheet` value of the dataset in `DATASET_CONFIGS` if there is one, otherwise with its `label`. |
| `Master` | Every variable name once, taken from the first dataset sheet in which it occurs, in the same layout. |

## Inputs

| File | Description |
|------|-------------|
| `neotree_scripts/<country>-scripts/*.json` | Neotree script files |
| `dictionaries/dictionary_<country>_<dataset>_enriched.xlsx` | Dictionary workbook, where it exists |
| `dictionaries/dictionary_<country>_<dataset>.xlsx` | Dictionary workbook otherwise |

## Outputs

| File | Description |
|------|-------------|
| `user_dictionaries/neotree_user_dict_zim.xlsx` | User dictionary for Zimbabwe |
| `user_dictionaries/neotree_user_dict_mwi.xlsx` | User dictionary for Malawi |

The folder is created if it does not exist. Existing files are replaced. For each dataset the console shows the number of rows, sections and scripts.

## Configuration

Set in the script.

| Setting | Default | Effect |
|---------|---------|--------|
| `NEOTREE_SCRIPTS_BASE` | `neotree_scripts` | Folder of the script files. Each subfolder named `<country>-scripts` is read. |
| `DICT_DIR` | `dictionaries` | Folder of the dictionary workbooks. |
| `OUTPUT_DIR` | `user_dictionaries` | Folder of the output workbooks. |
| `USE_ENRICHED_DICT` | `TRUE` | Read the `_enriched.xlsx` copies when they exist. |
| `DERIVED_KEYS` | list of keys | Derived variables to add. A key is added only if it is also in the dictionary, where `DERIVED_VARIABLES` of `00_build_dictionary.r` puts it. |
| `DATASET_CONFIGS` | per country | Datasets to include, in sheet order, with `key`, `label` and optionally `sheet`. |
| `FACILITY_SCRIPT_MAP` | per country and dataset | Script identifiers. |

To add a dataset, add it to `DATASET_CONFIGS` and to `FACILITY_SCRIPT_MAP`.

## How to run it

```r
source("00_build_dictionary/00d_build_user_dictionary.r")
```

or `Rscript 00_build_dictionary/00d_build_user_dictionary.r`. Packages used: `openxlsx`, `jsonlite`.

# Data dictionaries

## Purpose

This folder holds the data dictionaries of the cleaning pipeline: one Excel workbook per country and dataset, listing the variables of that dataset, their types, their allowed codes and the rules for removing personal data.

The workbooks are written by the scripts in `00_build_dictionary/`. They are generated files: a rebuild replaces them, so a change made by hand in a workbook is lost. Permanent changes are made in the build script (see `00_build_dictionary/README.md`).

## Files

Each dataset has two workbooks:

| File | Written by | Content |
|------|------------|---------|
| `dictionary_<country>_<dataset>.xlsx` | `00_build_dictionary.r` | The base dictionary. |
| `dictionary_<country>_<dataset>_enriched.xlsx` | `00c_enrich_dictionary_from_scripts.r` and `00e_enrich_from_public_dictionary.r` | A copy of the base dictionary with extra documentation columns in the `Variables` sheet. |

`<country>` is `zim` or `mwi`. The datasets are:

| Dataset | `zim` | `mwi` |
|---------|:-----:|:-----:|
| `admissions` | yes | yes |
| `discharges` | yes | yes |
| `maternal_outcomes` | yes | yes |
| `phc_admissions` | yes | yes |
| `phc_discharges` | yes | yes |
| `neolab` | yes | yes |
| `baseline` | yes | |
| `infections` | yes | |
| `twenty_8_day_follow_up` | yes | |
| `combined_maternity_outcomes` | | yes |
| `dhis2_maternal_outcomes` | | yes |
| `maternity_completeness` | | yes |

The cleaning pipeline reads the base workbook, `dictionary_<country>_<dataset>.xlsx`, and from it the sheets `Variables`, `ValueMaps` and `PII_Patterns`. If the workbook for a dataset does not exist, `00_setup.r` uses the workbook of the dataset named in `DICT_FALLBACK`, where one is defined. The enriched workbooks are read by `00d_build_user_dictionary.r`.

## Sheets of a base workbook

| Sheet | One row per |
|-------|-------------|
| `Variables` | variable |
| `ValueMaps` | allowed option of a variable |
| `PII_Patterns` | column-name pattern that marks personal data |
| `ReviewNeeded` | variable that the build script flags for checking |

### `Variables`

| Column | Meaning |
|--------|---------|
| `environment` | Country name. |
| `dataset` | Country code and dataset, as `<COUNTRY>_<dataset>`. |
| `question_key` | Name of the variable: the data key name in lower case with everything except letters and digits removed. Unique within the sheet. |
| `raw_value_column` | Name of the column holding the value in the input data: `question_key` followed by `.value`. Empty for derived variables. |
| `raw_label_column` | Name of the column holding the label in the input data: `question_key` followed by `.label`. Empty for derived variables. |
| `variable_label` | Label of the data key. |
| `raw_data_type` | Data type of the key in the data-key export. `derived` for variables computed by the pipeline. |
| `r_type` | Type used by the pipeline: `numeric`, `boolean`, `categorical`, `datetime` or `object`. Empty when the data type is not known to the build script. |
| `section` | Titles of the scripts that use the key, sorted and separated by `; `. For legacy and derived variables, a fixed text naming their origin. |
| `harmonised_variable_name` | The key name in lower case with underscores between words. |
| `use_in_analysis` | `FALSE` for free-text keys, summary-table keys and draft keys; `TRUE` otherwise. |
| `weight_unit` | `grams` for weight variables; otherwise empty. |
| `confidential` | Confidentiality flag of the key in the data-key export. |
| `record_id_role` | Role of record-level system keys such as the record identifier, the facility and the timestamps; otherwise empty. |
| `linkage_role` | `primary_linkage_key` for `uid`, `secondary_linkage_key` for `facility`; otherwise empty. |
| `suggested_plausible_min` | Lowest accepted value of a numeric variable. Empty for no lower limit. |
| `suggested_plausible_max` | Highest accepted value of a numeric variable. Empty for no upper limit. |
| `cleaning_note` | Free-text note. Filled for legacy and derived variables. |
| `key_unique_key` | Identifier of the data key in the export. Empty for legacy and derived variables. |
| `pii_tier` | `1` when `confidential` is `TRUE`; `2` when `question_key` matches a pattern of the `PII_Patterns` sheet; `quasi` for a quasi-identifier; otherwise empty. |
| `pii_category` | Kind of personal data: `direct_identifier` for tier 1, the category of the matching pattern for tier 2. |
| `pii_matching_pattern` | The pattern that gave tier 2. |

### `ValueMaps`

| Column | Meaning |
|--------|---------|
| `question_key` | Variable the option belongs to. Matches `question_key` in `Variables`. |
| `raw_code` | Code of the option as stored in the data. |
| `option_label` | Display label of the option. |
| `option_order` | Position of the option within the variable. Options of the current version of the key come first, followed by options that exist only in other versions of the key, then options added by the build script. |
| `option_uuid` | Identifier of the option in the data-key export. Empty for options added by the build script. |
| `canonical_code` | Code that the pipeline writes for this option. Equal to `raw_code` unless the build script sets a different one. |

A variable may have several rows with the same `raw_code` and different labels; each label is kept once per variable.

# Module 00: Setup and Configuration

## Purpose

Loads the libraries, reads the user settings and the data dictionary, defines the helper functions shared by the other modules, and builds the configuration list `cfg`.

## When it runs

First. Every other module sources `00_setup/00_setup.r` at its top, so the settings, helpers and `cfg` are rebuilt each time a module is sourced.

## What it does

1. Applies the default to every user setting that is not already defined in the calling environment.
2. Creates the output folder and a run folder inside it, named after the input file without its `.csv` extension.
3. Starts logging to the console and to `<file stem>.log` in the run folder.
4. Checks `COUNTRY`, `DATASET` and `DATA_SOURCE` and stops if a value is not accepted.
5. Detects the export style of the input file and logs it.
6. Resolves the dictionary, output, report and paired-file paths.
7. Loads the dictionary sheets `Variables` and `ValueMaps`. Stops if the dictionary file does not exist.
8. Derives the feature lists and lookups from the dictionary and assembles `cfg`.
9. Compares the header of the input file with the dictionary and reports columns the dictionary does not cover.
10. Defines the PII patterns, the completion-marker path and the guard `assert_pii_removed()`.

## Configuration

Each setting is assigned only if it does not already exist, so a value set before the file is sourced (for example by `run_all.r`) is kept.

| Setting | Default | Effect |
|---------|---------|--------|
| `COUNTRY` | `"ZIM"` | `"ZIM"` or `"MWI"`. Trimmed and converted to upper case. |
| `DATASET` | `"admissions"` | Dataset type; see *Datasets* below. Trimmed and converted to lower case. |
| `DATA_SOURCE` | `"auto"` | Accepts `auto`, `database`, `metabase`, `mixed` or `unknown`. It does not change how anything is parsed, and is replaced by the detected export style. |
| `CSV_FILEPATH` | a file in `input/` | Path to the raw CSV. |
| `DICT_FILEPATH` | `NULL` | Dictionary path. `NULL` resolves it automatically; see *Path resolution*. |
| `OUTPUT_CSV`, `OUTPUT_RDS` | `NULL` | Paths of the cleaned outputs. `NULL` gives `<file stem>_cleaned.csv` and `<file stem>_cleaned.rds` in the run folder. |
| `OUTPUT_DIR` | `"output"` | Base folder for everything the pipeline writes. |
| `REPORT_DIR` | `NULL` | `NULL` gives `reports/` in the run folder. A path writes the reports there. `FALSE` or `""` suppresses the module reports (`cfg$report_dir` is `NULL`). |
| `NEOTREE_SCRIPTS_DIR` | `NULL` | Folder of Neotree script metadata used by Module 16. `NULL` gives `neotree_scripts/` in the pipeline folder. |
| `SAVE_DEIDENTIFIED` | `FALSE` | Module 00a writes `<file stem>_deidentified.csv`. |
| `SAVE_STAGE1_CHECKPOINT` | `FALSE` | Module 10 writes a checkpoint RDS after its first stage. |
| `SAVE_HARMONISED` | `FALSE` | Module 00b runs and writes the harmonised CSV and RDS. |
| `SAVE_NA_CODED` | `TRUE` | Module 16 writes the cleaned data with each `NA` replaced by its reason code. |
| `SAVE_NA_REASONS_LONG` | `FALSE` | Module 16 writes the long table of `NA` reasons. |
| `SKIP_DEDUP_STAGE2` | `TRUE` for `infections` and `neolab`, otherwise `FALSE` | Module 10 skips its patient-level stage. |
| `RESOLVE_NEOLAB_DATEBCT` | `TRUE` | Module 14a fills missing `datebct` values from the admissions file. Used only when the dataset is `neolab`. |
| `UID_REPAIR_SEPARATORS` | `c(",", "/")` | Characters Module 02 treats as a mistyped hyphen in a `uid`. |
| `RESERVED_COLUMN_RENAMES` | for `phc_discharges`: `facility.value` to `facilityname.value`, `facility.label` to `facilityname.label` | Per dataset, standardised column names that Module 01 renames so that they do not share a name with a key column. |
| `LABEL_VALUE_RULES` | for Malawi `admissions`: `antenatalcare` with the parser `anc_visit_count` | Per country and dataset, fields whose answer Module 05 reads from the `.label` column when the `.value` column holds no valid value. |

### Datasets

`admissions`, `discharges`, `maternal_outcomes`, `phc_admissions`, `phc_discharges`, `combined_maternity_outcomes`, `dhis2_maternal_outcomes`, `maternity_completeness`, `joined_admissions_discharges`, `neolab`, `baseline`, `infections`, `twenty_8_day_follow_up`.

## Path resolution

**Dictionary.** With `DICT_FILEPATH` unset, the path is `dictionaries/dictionary_<country>_<dataset>.xlsx`. If that file does not exist and the dataset has a fallback type whose dictionary exists, the fallback dictionary is used.

| Dataset | Fallback type |
|---------|---------------|
| `joined_admissions_discharges`, `phc_admissions`, `baseline` | `admissions` |
| `phc_discharges` | `discharges` |
| `dhis2_maternal_outcomes` | `combined_maternity_outcomes` |
| `maternity_completeness` | `maternal_outcomes` |

**Paired file.** `.resolve_paired_csv(csv_filepath, dataset)` looks for the other half of an admissions/discharges pair (`admissions` with `discharges`, `phc_admissions` with `phc_discharges`) in the folder of the input file. It first swaps the dataset token in the input file name. If that file does not exist, it lists files named `<country>_[db_|mb_]<paired dataset>_<stamp>.csv`, where the stamp is 12 digits, 8 digits or `YYYY-MM-DD`, and takes the last one in sorted order. It returns `list(dataset, path)`. Both are `NULL` when the dataset has no pair; `path` is `NULL` when no file is found. Only the path is resolved; the file is not read.

## Format detection

`.detect_data_source(csv_filepath, n_rows = 500)` reads the header and the first rows as text and returns `list(source, reason)`.

| Evidence | Style |
|----------|-------|
| Header has `Unique Key`, `Started At`, `Completed At` or `Ingested At` | `metabase` |
| Header has `unique_key`, `started_at`, `completed_at` or `ingested_at` | `database` |
| Values include month-name datetimes and no ISO datetimes | `metabase` |
| Values include ISO datetimes and no month-name datetimes | `database` |
| Values include both, or ISO datetimes together with thousands-separated numbers | `mixed` |

`source` is the style when header and values agree or only one is recognised, `mixed` when they differ, and `unknown` when neither is recognised or the file cannot be read. `reason` holds the counts. The result is logged and stored in `cfg$data_source`.

## Shared value parsers

### `parse_datetime_by_shape(x)`

Returns a POSIXct (UTC) vector. Each value is trimmed and parsed by the rule for its own shape. Empty values and the text `NA` are `NA`.

| Shape | Examples | Read as |
|-------|----------|---------|
| ISO | `2023-10-19`, `2023-10-19 22:00:00`, `2023-10-19T22:00:00Z`, `2023/10/19` | Year, month, day, with an optional time. A trailing `Z` or UTC offset after a time is dropped; the time is kept as written. |
| Day first | `19/10/2023`, `19-10-2023`, `19.10.2023`, `19/10/23 10:30 PM` | Day, month, year, with an optional 12-hour or 24-hour time. A two-digit year is read as 20yy. A value valid only as month/day/year becomes `NA`. |
| Month name | `March 2, 2026, 12:33 AM`, `2 March 2026`, `19-Oct-2023` | Month name identified by its first three letters, in any case, with an optional time. |
| Anything else | free text, digits without separators | `NA` |

The attribute `counts` on the result is a named integer vector: `iso`, `day_first`, `month_name`, `offset_dropped`, `month_first_rejected`, `unparsed`.

### `parse_numeric_by_shape(x)`

Returns `list(value, counts)`. `value` is a numeric vector.

| Value | Read as |
|-------|---------|
| `3500`, `3.5`, `-2` | the number |
| `3,500`, `1,234,567.8` | 3500, 1234567.8 (thousands separators removed) |
| `3,5`, `36,75` | 3.5, 36.75 (decimal comma, one or two digits after it) |
| text holding one run of digits, e.g. `ANC4`, `36.5 C` | that number, without a sign |
| text holding several runs of digits, e.g. a date, `10-12`, `1e5`, `0x1A` | `NA` |
| text with no digit | `NA` |

`counts` is a named integer vector: `plain`, `thousands`, `decimal_comma`, `fallback`, `multi_number_rejected`, `non_numeric`.

| Object | Values |

| `NEOTREE_TRUE_TOKENS` | `true`, `yes`, `y`, `1`, `t` |
| `NEOTREE_FALSE_TOKENS` | `false`, `no`, `n`, `0`, `f` |

## PII definitions and guard

| Object | Content |
|--------|---------|
| `PII_FALLBACK_PATTERNS_DEFAULT` | Built-in column-name patterns: names ending in `name.value`, `cell.value`, `phone.value`, `address.value`, `uidbid.value`, `uiddc.value` or `drid.value`; names containing `hcwid`, `hospnum`, `neotreeid` or `stuid`; and a mother's date-of-birth column with a `.value` or `.label` suffix. |
| `PII_SHEET_PATTERNS` | Patterns read by `load_pii_patterns(dict_path)` from the `pattern` column of the dictionary sheet `PII_Patterns`; `NULL` if the sheet cannot be read or is empty. |
| `PII_TIER2_PATTERNS` | The union of the two lists above. |
| `PII_VALUE_PATTERNS` | Value patterns; see the table below. |
| `PII_VALUE_SCAN_EXEMPT` | Key and system columns that are never redacted: `uid`, `facility`, `uniquekey`, `startedat`, `completedat`, `ingestedat`, `startedatdischarge`, `completedatdischarge`, `ingestedatdischarge`, `scriptversion`, `scriptid`. |

| Value pattern | Matches |
|---------------|---------|
| `phone_international` | A whole value of `263` and 9 digits, or `265` and 7 to 9 digits, with an optional leading `+`. |
| `phone_local_zw` | A whole value of `0`, then `6` or `7`, then 8 digits. |
| `phone_local_mwi` | A whole value of `0`, then `8` or `9`, then 8 digits. |
| `email` | An email address anywhere in the value. |

`pii_value_hits(x, pattern)` trims the values and returns a logical vector marking those that match.

`write_pii_marker(input_path, run_id, n_cols_removed, n_values_redacted)` writes the marker file: completion time, run id, pipeline version, input path, size and modification time, dictionary path and MD5 checksum, number of column-name patterns, and the two counts.

`assert_pii_removed(df, stage, check_run_id = FALSE, value_exempt = character(0))` returns `TRUE` invisibly or stops with an error. It checks, in order:

1. The marker file exists and holds the required fields.
2. The marker describes the current input: same path, size and modification time; written after the input was last modified; same dictionary checksum.
3. With `check_run_id = TRUE`, the attribute `neotree_pii_run_id` of `df` equals the run id in the marker.
4. No column of `df` belongs to a variable flagged confidential in the dictionary, and none matches a pattern in `PII_TIER2_PATTERNS`. Each column is tested under its own name, as `<base>.value`, as `<question_key>.value` when it carries a harmonised name, and with the Module 01 reserved renames undone.
5. No value matches a pattern in `PII_VALUE_PATTERNS`. Date, date-time, logical and list columns are skipped, as are the columns in `PII_VALUE_SCAN_EXEMPT`, their harmonised names, and those named in `value_exempt`.

Error messages give column names, pattern names and counts of cells, never values.

# Module 00a: PII Detection and Removal

## Purpose

Loads the raw CSV, removes the columns that hold personally identifiable information (PII), blanks individual values that look like PII, and writes an audit report and a completion marker.

## When it runs

After Module 00 and before Module 01. It is the only module that reads the raw CSV in full.

## What it does

The file is read with every column as text. Column names are normalised first: surrounding whitespace is trimmed, spaces around dots are removed, all remaining whitespace and underscores are removed, and the name is converted to lower case. `Unique Key` and `unique_key` both become `uniquekey`.

Any completion marker left by an earlier run is deleted before the file is read.

### Tier 1: columns flagged in the dictionary

Every column named in `cfg$pii_columns` is removed. These are the value and label columns of the variables flagged `confidential` in the dictionary.

### Tier 2: columns matched by name

Every remaining column whose name matches a pattern in `PII_TIER2_PATTERNS` is removed. The list is the union of the patterns in the dictionary sheet `PII_Patterns` and the built-in defaults in `00_setup.r`. Matching ignores case. If the sheet cannot be read, only the built-in defaults apply and a warning is logged.

The built-in defaults cover these kinds of column:

| Kind | Columns matched |
|------|-----------------|
| Personal names | names ending in `name.value` |
| Telephone numbers | names ending in `cell.value` or `phone.value` |
| Addresses | names ending in `address.value` |
| Hospital numbers | names containing `hospnum` |
| Record identifiers | names containing `neotreeid`; names ending in `uidbid.value` or `uiddc.value` |
| Staff identifiers | names containing `hcwid` or `stuid`; names ending in `drid.value`; `firm` and `concall` (consultant on call), `hcwsigdis` (discharge signature), `dataentryname` and `dataentrynameother` (person entering the data), value and label |
| Mother's date of birth | `motherdob` and its variants, value and label; the yes/no field `motherdobyn` is kept |

### Quasi-identifiers

Columns whose names match one of the patterns below are listed in the audit report and kept in the data.

`village`, `district`, `province`, `address`, `matagedate` anywhere in the name; `tribe.value`, `ethnicity.value`, `religion.value` at the end of the name.

### Tier 3: values matched by pattern

Each value in the remaining columns is trimmed and tested against every pattern in `PII_VALUE_PATTERNS` (phone numbers, email addresses, a three-part number pattern, and the two national identity number shapes; see the Module 00 README). A matching value is set to `NA`.

### Exempt key and system columns

The columns in `PII_VALUE_SCAN_EXEMPT` are tested in the same way but never changed: `uid`, `facility`, `uniquekey`, `startedat`, `completedat`, `ingestedat`, `startedatdischarge`, `completedatdischarge`, `ingestedatdischarge`, `scriptversion`, `scriptid`. A match in one of them is logged as a warning and counted in the audit report.

### Completion marker and guard

After removal and redaction, the module builds a run id from the clock and the process id, calls `write_pii_marker()` to write `00a_pii_removal_complete.dcf` in the run folder, and attaches the run id to the data frame as the attribute `neotree_pii_run_id`. The marker describes the raw input file, whether or not the de-identified copy is saved.

The guard `assert_pii_removed()` in `00_setup.r` reads the marker back. Module 01 calls it with `check_run_id = TRUE` before using `df_raw`, and the modules that write row-level data call it before writing. It stops the run if the marker is missing or does not describe the current input and dictionary, or if a Tier 1 or Tier 2 column or a Tier 3 value is present.

### Audit report

The report holds column names and counts only; no cell values are written.

- Country, dataset, detected export style and source file.
- Number of columns removed by the dictionary flag and by name patterns, number flagged, number of values redacted, and number of columns remaining.
- The names of the removed columns, marked `[dict]` or `[pattern]`.
- The names of the quasi-identifier columns.
- For each column with redacted values, the number redacted.
- The exempt columns present and, for each one with matches, the pattern name and the number of matching values.

## Inputs

| Object / file | Description |
|---------------|-------------|
| Raw CSV at `cfg$csv_filepath` | Read with all columns as character |
| `cfg$pii_columns` | Column names for Tier 1 |
| `PII_TIER2_PATTERNS`, `PII_VALUE_PATTERNS`, `PII_VALUE_SCAN_EXEMPT` | Defined in `00_setup.r` |

## Outputs

| Object / file | Description |
|---------------|-------------|
| `df_raw`, `df_raw_deidentified` | De-identified data frame with normalised column names and the attributes `neotree_pii_n_removed`, `neotree_pii_n_redacted` and `neotree_pii_run_id` |
| `reports/00a_pii_audit_report.txt` | Audit report; not written when reports are suppressed |
| `00a_pii_removal_complete.dcf` | Completion marker, in the run folder |
| `<file stem>_deidentified.csv` | Written to the run folder only when `cfg$save_deidentified` is `TRUE`; `cfg$csv_filepath` is then set to this file |

## Functions

`clean_name_simple(name)` returns the normalised column name.

`remove_pii(df, pii_columns = character(0), report_filepath = NULL)` returns the de-identified data frame, with the number of columns removed and values redacted as attributes.

## Configuration

| Setting | Effect |
|---------|--------|
| `SAVE_DEIDENTIFIED` | `TRUE` writes the de-identified CSV. PII removal runs in either case. |
| `REPORT_DIR` | Location of the audit report; no report when reports are suppressed. |

# Module 00b: Rename Columns to Harmonised Names

## Purpose

Produces a copy of the cleaned dataset in which each column carries the harmonised variable name given in the data dictionary.

## When it runs

After Module 15, on `df_clean`. It stops if `df_clean` does not exist. It does nothing unless `cfg$save_harmonised` is `TRUE`.

## What it does

For each column, the suffix `.valuedischarge` or `.value` is removed to give the base name.

| Base name | Result |
|-----------|--------|
| A `question_key` in `cfg$harmonised_map` | The column is renamed to its harmonised name. |
| Not in the map | The column keeps its name. |

Columns with any other suffix, such as `.label`, are looked up under their full name.

Before writing, `assert_pii_removed()` checks the renamed data frame. The data frame is then written as CSV, with `NA` as an empty field, and as RDS.

## Inputs

| Object | Description |

# Module 02: Frame Shift Correction

## Purpose

Repairs `uid` values in which another character was typed in place of the hyphen, and removes rows whose `uid` is empty.

## When it runs

After Module 01.

## What it does

If the data frame has no `uid` column, it is returned unchanged. Otherwise the `uid` values are trimmed and handled in this order.

### 1. Repair of separators

A `uid` made of 3 to 6 letters or digits, one of the characters in `cfg$uid_repair_separators`, and then one or more letters or digits is repaired by replacing that character with a hyphen. With the default separators, `XXXX,0001` and `XXXX/0001` both become `XXXX-0001`.

### 2. Removal of empty UIDs

A row is removed when its `uid` is `NA`, empty, or one of `na`, `null`, `nan`, `none`, `n/a`, `<na>` in any case. No other row is removed.

### 3. Confirmation of repairs

When at least one `uid` was repaired, the `uid` and `facility` columns of the paired admissions or discharges file (`cfg$paired_csv_filepath`) are read, and each repair is given a status. The repair is applied whatever the status.

| Status | Meaning |
|--------|---------|
| `confirmed` | The repaired `uid` is in the paired file with the same facility. |
| `confirmed (other facility)` | The repaired `uid` is in the paired file with a different facility. |
| `unconfirmed` | The repaired `uid` is not in the paired file. |
| `unchecked` | There is no paired file, or it could not be read, or it lacks a `uid` or `facility` column. |

A repair is also marked when the repaired `uid` and facility already occur on another row of the same file that was not repaired. The rows are left as they are.

### 4. UIDs without a hyphen

Rows whose `uid` has no hyphen are kept and reported in two groups.

| Group | Rule | Example |
|-------|------|---------|
| Standard length | Exactly 8 letters or digits | `XXXX0001` |
| Other | Any other value without a hyphen | `XX01` |

## Inputs

| Object / file | Description |
|---------------|-------------|
| `df` | Data frame from Module 01 |
| `cfg$uid_repair_separators` | Characters treated as a mistyped hyphen |
| `cfg$paired_csv_filepath` | Paired raw CSV, or `NULL`. Only its `uid` and `facility` columns are read, and only when a repair was made. |

## Outputs

| Object / file | Description |
|---------------|-------------|
| `df` | Data frame with repaired `uid` values and without the empty-`uid` rows |
| `reports/02_frame_shift_report.txt` | Separator set and paired file used; rows on entry, repaired, removed and remaining; number of repairs by status; one line per distinct repair with the original and repaired `uid`, facility, separator, number of rows and status; the `uid` values of the removed rows; the UIDs without a hyphen, by group. |
| `reports/02_frame_shift_dirty_rows.csv` | The removed rows. Written only when at least one row is removed, after `assert_pii_removed()` has checked them. |

## Functions

`remove_frame_shift(df, separators = NULL, paired_csv_filepath = NULL, report_filepath = NULL, csv_filepath = NULL)` returns the corrected data frame. When `separators` is `NULL`, `cfg$uid_repair_separators` is used, or comma and slash if `cfg` is not available.

`.uid_separator_class(seps)` returns a regular-expression character class built from the separator characters, or `NULL` if there are none, in which case no `uid` is repaired.

# Module 04: Dictionary-Based Value Cleaning

## Purpose

Rewrites categorical values as the canonical codes defined in the data dictionary, wherever a value can be matched to exactly one code. Values that cannot be matched are left as they are.

## When it runs

After Module 03. All columns are character at this point.

## What it does

Four steps run in this order. A column is matched to its dictionary entry by its name with the `.value` or `.valuedischarge` suffix removed.

### 1. Multi-select encoding

Applies to columns with a dictionary entry, and to `resus` and `delivinter`. Only values that start with `[` are examined.

| Value | Result |
|-------|--------|
| Quoted list, `["A","B"]` or `["A", "B"]` | `{A,B}` |
| Unquoted list, `[A, B]`, where every item is a raw or canonical code of the column (in any case) | `{A,B}` |
| Unquoted list with an item that is not a code of the column, or in a column with no dictionary entry | unchanged |
| List with an empty item, or any other value starting with `[` | unchanged |

Items are written as they appear in the value, without surrounding spaces.

### 2. Canonical codes

Applies to columns with a dictionary entry. The targets are the entry's canonical codes; if it has none, its raw codes are used instead. Each distinct value of a column is resolved by the first rule that fits:

1. It is a canonical code, exactly as written: kept.
2. It matches a canonical code when case is ignored: replaced by the canonical spelling.
3. It matches a raw code when case is ignored: replaced by that code's canonical code.
4. It matches an option label when case is ignored: replaced by that label's canonical code.
5. It is `true`, `yes`, `t` or `y`, or `false`, `no`, `f` or `n` (in any case), and every canonical code of the variable is one of `Y`, `N`, `U`: replaced by the variable's yes or no code.
6. Otherwise: left unchanged and counted as unresolved.

Case-insensitive matching is used only where it is unambiguous. If two codes or labels of a variable differ only by case and lead to different canonical codes, that spelling is not matched without regard to case, and only rule 1 applies to it.

A multi-select value, `{A,B}`, is split on commas and each item is resolved by rules 1 to 5. If every item resolves, the value is rewritten with the canonical codes, as `{A,B}` without spaces. If any item does not resolve, the whole value is left unchanged and counted as unresolved.

Option labels whose dictionary code is empty are not used for matching.

### 3. `modedelivery`

In `modedelivery` and `modedelivery.value`, a value that is exactly one of the text codes named in `MODEDELIVERY_MAP` is replaced by the numeric code given there. Other values are unchanged.

### 4. Thompson score columns

In every column whose name starts with `thomp` (in any case), a value made of a number followed by `=` and a label, such as `2 = Label`, is replaced by the number alone.

## Inputs

| Object | Description |
|--------|-------------|
| `df` | Data frame from Module 03 |
| `cfg$value_map_list` | List with one entry per dictionary variable: `allowed_codes` (raw codes), `canonical_codes`, `label_to_code` (option label to canonical code) and `code_to_canonical` (raw code to canonical code). Built in `00_setup.r` from the dictionary value maps. |

## Outputs

| Object / file | Description |
|---------------|-------------|
| `df` | Data frame with values rewritten by the four steps |
| `reports/04_dictionary_cleaning_report.txt` | Results of step 2 only: number of columns checked; totals of replacements, deletions and unresolved values; and, for each column, every replaced value with its replacement and every unresolved value, each with its number of records. |

Steps 1, 3 and 4 write their counts to the pipeline log.

## Functions

| Function | Returns |
|----------|---------|
| `normalise_multiselect_encoding(df, value_map_list)` | Data frame after step 1 |
| `clean_values_using_dict(df, value_map_list, report_filepath = NULL)` | Data frame after step 2 |
| `harmonise_modedelivery(df)` | Data frame after step 3 |
| `strip_thompson_labels(df)` | Data frame after step 4 |

# Module 05: Forward Fill Placeholder Values and Label-to-Value Rules

## Purpose

Recovers answers that are stored only in a label column. Configured fields are read from their label by a field-specific parser; a set of fixed placeholder words is copied from a label column into its paired value column where the value is missing.

## When it runs

After Module 04.

## What it does

### 1. Label-to-value rules

`cfg$label_value_rules` (from `LABEL_VALUE_RULES` in `00_setup/00_setup.r`) lists, for the current country and dataset, fields and the parser that reads each one. For each field the parser reads the `.value` and `.label` columns and fills `.value` where it holds no valid value and the label gives one. A valid `.value` is never changed. The pairs handled here are skipped by step 2.

The parser `anc_visit_count` (antenatal care visits, Malawi `admissions`) works as follows.

| `.value` | `.label` | Result in `.value` | `<field>_source` |
|----------|----------|--------------------|------------------|
| whole number, 0 or more | any | unchanged | `raw_numeric_value` |
| empty or not a whole number | `N ANC visit` or `N ANC visits` (any case, extra spaces allowed), or a plain whole number | `N` | `raw_exact_label` |
| empty or not a whole number | `None` | `0` | `raw_exact_label` |
| empty or not a whole number | `More than 4 ANC visits`, `More than 8 ANC visits` | empty | `raw_range_label` |
| empty or not a whole number | anything else, such as `Not sure`, `ANC visits` with no number, or question text | empty | `unresolved` |

When a valid `.value` and a label count disagree, the `.value` is kept and the number of such rows is reported and logged as a warning. The parser adds the bare column `<field>_source` to the data frame. Module 15 derives `antenatalcare_category` from the final count and this column.

The rule is configured for Malawi `admissions` only.

Columns are paired by name: each `.value` column with the `.label` column of the same variable, and each `.valuedischarge` column with its `.labeldischarge` column. A value column with no label column is skipped.

In each pair, a row is filled when the value is `NA` and the label is exactly one of the placeholders below. The label text is copied into the value column as it is.

| Group | Placeholders |
|-------|--------------|
| None / normal | `None`, `Normal`, `Norm`, `none`, `normal`, `norm`, `NONE`, `NORMAL`, `NORM` |
| True / false | `True`, `False`, `TRUE`, `FALSE` |
| Yes / no | `Yes`, `No`, `YES`, `NO`, `Y`, `N` |

Matching is case-sensitive. Labels in any other form are not copied. The label columns are kept.

| Object / file | Description |
|---------------|-------------|
| `df` | Data frame with values read from labels and placeholders copied into the value columns, plus `<field>_source` for each rule |
| `reports/05_forward_fill_placeholder_report.txt` | Number of placeholders checked, total number of values filled and, for each pair with a fill, the number of values filled. # Module 10: Remove Duplicate Rows

## Purpose

Removes duplicate rows in two stages, keeping the most complete record each time, and optionally saves a checkpoint of the result.

## When it runs

After Module 09. Modules 11 to 14 each read the data frame produced here.

## What it does

### Stage 1: one row per visit

Rows are grouped by `uid`, `facility` and whichever of these visit-date columns are present: `startedat`, `startedatdischarge`, `datetimeadmission.value`, `dateadmission.value`, `datebct.value`, `completedat`, `completedatdischarge`.

Within each group the row with the fewest missing values in the remaining columns is kept. When rows are equally complete, a row whose `uniquekey` is not in timestamp form (`YYYY-MM-DDT...`) is kept ahead of one whose `uniquekey` is; otherwise the first row in the data frame is kept.

### Stage 2: one row per patient

Rows are grouped by `uid` and `facility`. Within each group the row with the fewest missing values in all other columns is kept. When rows are equally complete, the row with the highest `uniquekey` (text order) is kept.

Stage 2 is skipped when `skip_stage2` is `TRUE`. Stage 1 still runs.

When Stage 2 is skipped, the module counts the rows that share `uid`, `facility` and `uniquekey` with another row. Modules 11 to 15 keep one row per such key, so these rows would be merged. The count is written to the report, and a warning is logged when it is above zero or when there is no `uniquekey` column.

### Stage 2, episode mode (admissions and discharges, main and PHC; maternal files)

When `DEDUP_MODE` is `"episode"` (the default), admissions and discharges (`admissions` and `discharges`, and the PHC files `phc_admissions` and `phc_discharges`) use episode mode instead of Stages 1 and 2 (`episode_ids.r`). Stage 1 is not applied, because rows with identical visit dates can belong to different babies.

1. **Same event.** Rows sharing `uid` and `facility` are collapsed only when their event times are within 1 hour, sex, birth weight (more than 100 g apart) and gestation (more than 1 week apart) do not disagree, and their readmission flags do not differ. A row joins a collapsed record only when it meets these conditions against every row already in it. The event time is the admission date-time (else the form start time) for admissions, and the form start time (else the discharge date-time) for discharges. The most complete row is kept.
2. **Baby.** Admission records sharing a `uid` are taken in date order; each joins the first baby under that `uid` it belongs to: identity differs means another baby; a readmission flag, or the same `uid` at another facility with two or more identity fields agreeing, means the same baby; otherwise Apgar at 5 minutes, mode of delivery, birth facility and maternal age decide (`probable`); with nothing to compare the record gets its own letter (`unresolved`).
3. **Stay.** The admission records of one baby are numbered 1, 2, 3 in date order.
4. **Discharges** take the baby and stay of the admission they fit under the same `uid` and `facility`: first the admission date-time carried on the discharge (within 1 hour, or exactly 2 hours), then the identity fields (two or more disagreeing means no fit), then the order of dates. If two admissions fit equally, the earlier is used (`ambiguous_link`). A discharge that fits no admission gets a stay of its own (`no_admission`). All discharge forms of one stay are kept; the form started last is marked `stay_form_primary`.

**Maternal files (births).** For Zimbabwe `maternal_outcomes` and Malawi `combined_maternity_outcomes`, one row is one baby at birth and `uid` is the baby's Neotree ID. Rows are collapsed by the rule in step 1, with birth outcome (live birth, stillbirth, miscarriage) and birth order (`typebirth`: Tw1, Tw2, Tr1 ...) added to the baby details and the maternal admission date-time as the clock. A birth happens once, so every record left is a baby of its own and gets its own letter under its `uid`; there is no `stay_no` and no key file. A record within 24 hours of an earlier one under the same `uid` is flagged `same_day_pair` when the baby details differ and `unresolved` when nothing differs; a later record in which nothing differs is also `unresolved`. The Malawi component files (`maternal_outcomes`, `dhis2_maternal_outcomes`, `maternity_completeness`) keep the current rule.

Columns added: `baby_id` (`uid`, a full stop and a letter), `stay_no`, `dedup_rows_merged`, `dedup_basis`, `dedup_flag` (`none`, or one or more of `unresolved`, `probable`, `ambiguous_link`, `link_doubt`, `no_admission`, `outcome_conflict`, `same_day_pair`, `collapsed_no_identity` (rows collapsed although no identity field could be compared), `no_uid`, separated by `;`), and on discharges `stay_form_primary`. The maternal files get the same columns without `stay_no`. The original `uid` is not changed. Rows without a `uid` are kept with `dedup_flag` `no_uid`.

The admissions run writes `<file_stem>_episode_keys.rds` to its output folder, with the name and md5 checksum of its input file and md5 checksums of every `.r` file in `00_setup`, `00_build_dictionary`, `00a_pii_detection_removal` and Modules 01 to 10, of every `.xlsx` file directly in `dictionaries/`, and of the dictionary file the admissions run read (its path, and its checksum taken when the setup read it; the key file is not written if the dictionary has changed since), and the rule's settings. The discharges run reads the key file of the paired admissions file and stops if it is missing or if any of these differ, so admissions must run first, and again after any change to that code or to the dictionaries. An admissions run in current mode removes an old key file.

In episode mode `uid` + `facility` is not unique, so Modules 11, 12, 14 and 15 keep one row per `uid` + `facility` + `uniquekey`, and Module 16 matches clean to raw rows on the same key. The run stops if two kept rows share `uid`, `facility` and `uniquekey`.

### Checkpoint

When `cfg$save_stage1_checkpoint` is `TRUE`, the deduplicated data frame is checked by `assert_pii_removed()` (`00_setup.r`) and then saved as an RDS file. A failed check stops the run. A failure to write the file is logged as a warning and the run continues.

# Module 11: Numeric Validation

## Purpose

Checks every numeric column: removes values that are not numbers, puts weights in grams and maternal age in years, and sets values outside the dictionary range to `NA`. Produces the numeric sub-frame used in the final merge.

## When it runs

After Module 10. Modules 11 to 14 each read the same data frame from Module 10 and each produce one sub-frame for Module 15.

## What it does

The sub-frame holds the key columns `facility`, `uid` and `uniquekey` and the columns of `cfg$num` present in `df`. Each numeric column goes through the steps below, in this order. A column is matched to the dictionary by its name without the `.value` or `.valuedischarge` suffix.

| Step | Applies to | Rule |
|------|-----------|------|
| 1. Non-numeric values | every numeric column | A value that `as.numeric()` cannot read becomes `NA`. |
| 2. Kilograms to grams | columns listed in `cfg$weight_cols` | A value of 20 or less is multiplied by 1000, e.g. `3.5` becomes `3500`. |
| 3. Hours to years | `matageyrs` | A value above 200 is divided by 8766 (hours in a year of 365.25 days) and rounded to one decimal place. |
| 4. Dictionary range | columns with an entry in `cfg$range_lookup` | A value below the minimum or above the maximum becomes `NA`. A missing minimum or maximum is not checked. |

After step 2, weight values below 100 g or above 5000 g are counted and reported as a warning. They are not changed.

### Derived column `mat_age_date_years`

`matagedate` holds maternal age in hours. When `matagedate.value` or `matagedate` is among the numeric columns, a new column is added:

`mat_age_date_years` = `matagedate` / 8766, rounded to a whole number of years.

Derived values below 9 or above 60 become `NA`. The `matagedate` column is not changed by this step.

### Duplicate keys

The first row for each key is kept. The key is `uid` and `facility`; for datasets that keep every visit (`cfg$skip_dedup_stage2` is `TRUE`) it is `uid`, `facility` and `uniquekey`.

## Inputs

| Object | Description |
|--------|-------------|
| `df` | Data frame from Module 10 |
| `cfg$num` | Names of the numeric columns |
| `cfg$weight_cols` | Dictionary variables whose `weight_unit` is grams |
| `cfg$range_lookup` | Table of `question_key`, `min`, `max`, taken from `suggested_plausible_min` and `suggested_plausible_max` of the numeric dictionary variables |

## Outputs

| Object / file | Description |
|---------------|-------------|
| `df_numeric` | Key columns and validated numeric columns, plus `mat_age_date_years` where `matagedate` is present |
| `reports/11_numeric_validation_report.txt` | Number of values changed at each step, out-of-range counts per column with the range applied, the weight columns, the maternal-age conversions, and the weight warning. Counts and column names only. |

## Function

`validate_numeric(df, cfg, report_filepath = NULL)` returns the numeric sub-frame.

# Module 14a: Resolve Missing Neolab `datebct` from Admissions

## Purpose

For the `neolab` dataset, fills missing blood-culture dates with the admission date-time of the same patient, in a new column. The original `datebct.value` column is not changed.

## When it runs

After Module 14 and before Module 15. It adds columns to `df_datetime`, which Module 15 then merges. For any dataset other than `neolab`, or when `cfg$resolve_neolab_datebct` is not `TRUE`, it returns `df_datetime` unchanged.

## What it does

Two columns are added to `df_datetime`.

| Column | Type | Content |
|--------|------|---------|
| `datebct_resolved` | POSIXct | `datebct.value` where present; otherwise the admission date-time; otherwise `NA` |
| `datebct_source` | character | `"original"`, `"from_admission"`, or `NA` when no date is available |

The steps are:

1. If no `datebct.value` is missing, `datebct_resolved` is a copy of `datebct.value` and `datebct_source` is `"original"` on every row. The admissions file is not read.
2. Otherwise the path of the admissions file is taken from `cfg$csv_filepath` by replacing `neolab` with `admissions` in the file name, e.g. `xxx_neolab_YYYYMMDD.csv` gives `xxx_admissions_YYYYMMDD.csv`.
3. Three columns are read from that file: `uid`, `facility` and `datetimeadmission.value` (or `datetimeadmission`). Column names are matched in lower case with spaces removed.
4. The admission date-time is parsed with `parse_datetime_by_shape()` (`00_setup.r`), as in Modules 09 and 14.
5. One row is kept per `uid` and `facility`: the one with the earliest admission date-time.
6. The result is joined to `df_datetime` on `uid` and `facility`, and the two columns are filled.

### When the lookup is not possible

| Situation | Result |
|-----------|--------|
| `datebct.value` is not in `df_datetime` | Both columns are added and are `NA` on every row. A warning is logged. |
| Admissions file not found or not readable, or it lacks `uid`, `facility` or the admission date-time column | `datebct_resolved` is a copy of `datebct.value`; `datebct_source` is `"original"` where a date is present and `NA` elsewhere. A warning is logged. |

## Inputs

| Object | Description |
|--------|-------------|
| `df_datetime` | Datetime sub-frame from Module 14 |
| `cfg$dataset` | The module acts only when this is `"neolab"` |
| `cfg$resolve_neolab_datebct` | See *Configuration* |
| `cfg$csv_filepath` | Path of the neolab input file, from which the admissions path is taken |
| Admissions input file | Read for the three columns named above |

## Outputs

| Object / file | Description |
|---------------|-------------|
| `df_datetime` | The same sub-frame with `datebct_resolved` and `datebct_source` added |
| `reports/14a_resolve_neolab_datebct_report.txt` | Paths of the two input files, rows in the sub-frame, number of missing `datebct.value`, and the number of rows per `datebct_source`. Written when no value is missing, when the admissions file is not found, and when the lookup completes. |

## Function

`resolve_neolab_datebct(df_datetime, cfg, report_filepath = NULL)` returns `df_datetime`, with the two columns added when the module acts.

|---------|--------|

# Module 16: NA Reason Coding

## Purpose

Gives every empty cell of the cleaned dataset a code that states why it is empty. The codes are written to companion files; the cleaned dataset itself is not changed.

## When it runs

After Module 15, on `df_clean`. `run_pipeline.r` runs the module only when the folder in `cfg$neotree_scripts_dir` exists; otherwise it logs a warning and continues without it.

## What it does

### The four codes

| Code | Name | Assigned when |
|------|------|---------------|
| `-6` | Redacted | The raw value matches a PII value pattern. |
| `-7` | Not applicable | The skip condition of the field in the Neotree script evaluates to false for that record, so the field was not shown. |
| `-8` | Invalid / removed | The raw cell held a value, the value is not PII, and the cleaned cell is empty. |
| `-9` | Unknown | Every other empty cell: the raw cell was empty, held a missing-value placeholder, or has no raw counterpart. |

The key columns `uid`, `facility` and `uniquekey` are not coded.

### Order of the rules

For each empty cell of the cleaned dataset:

1. If the raw value matches a PII pattern, the code is `-6`. Nothing overrides it.
2. Otherwise, if a skip condition is found for the field and evaluates to false, the code is `-7`. This applies whether the raw cell was empty or not.
3. Otherwise, if the raw cell held a value, the code is `-8`.
4. Otherwise the code is `-9`.

### Raw values

The module reads the input CSV (`cfg$csv_filepath`) again, with every column as text.

- Each row of the cleaned dataset is paired with the first raw row that has the same `uid`.
- Each cleaned column is paired with the raw column of the same name, compared in lower case and without punctuation, with the suffix `.value` or `.valuedischarge` or with no suffix. A cleaned column with no such raw column has no raw value.

A raw value counts as empty when, after trimming spaces, it is blank or one of `nan`, `none`, `na`, `n/a`, `null`, `NaN`, `None`, `NA`, `N/A`, `NULL`.

### PII value patterns

A raw value is treated as PII when it matches one of the patterns in `PII_PATTERNS_16`:

| Pattern | Shape |
|---------|-------|
| `phone_international` | Whole value is a Zimbabwe or Malawi country prefix followed by the subscriber digits, with or without a leading `+` |
| `phone_local_zw`, `phone_local_mwi` | Whole value is a ten-digit local mobile number |
| `email` | Value contains an e-mail address |
| `nhs_number` | Whole value is three, three and four digits separated by hyphens or spaces |

### Skip logic

`load_all_scripts()` reads every file whose name ends in `metadata.json` in the `zim-scripts/` and `mwi-scripts/` subfolders of `cfg$neotree_scripts_dir`. For every field on every screen it stores one condition:

- the screen condition, if the field has none of its own;
- the field condition, if the screen has none;
- `(screen condition) and (field condition)`, if both exist.

A field with no condition is always shown and never receives `-7`.

Each record is assigned a script by `resolve_script_id()`, in this order:

1. the value of the raw `scriptid` (or `script_id`) column, if it is listed in `EXACT_MATCH_SCRIPT_IDS`;
2. for Malawi maternal datasets, a fixed script if the raw value is listed in `MWI_MATERNAL_FIREBASE_IDS`;
3. the entry of `FACILITY_SCRIPT_MAP` for the country, the dataset and the record's `facility`.

Before the look-up, `normalise_dataset_name()` maps `combined_maternity_outcomes`, `dhis2_maternal_outcomes` and `maternity_completeness` to `maternal_outcomes`, and `infections` to `neolab`. Other dataset names are used unchanged. A record with no matching script is not evaluated for skip logic.

The condition for a field is found by the cleaned column name, in lower case and without punctuation. `translate_condition()` turns it into an R expression:

| In the script | Read as |
|---------------|---------|
| `$FieldKey` | the raw value of that field for the record, as text |
| `=` | equal to |
| `!=`, `>`, `<`, `>=`, `<=` | unchanged |
| `'text'` | the text |
| `true`, `false` | `TRUE`, `FALSE` |
| `and`, `or` | both, either |
| `( )` | grouping |

The value of `$FieldKey` is taken from the raw column that corresponds to a column of the cleaned dataset. A field with no such column, or with an empty raw value, is read as missing.

The cell receives `-7` only when the expression returns `FALSE`. If the expression returns `TRUE`, returns a missing result, cannot be parsed or raises an error, the cell keeps the code from rule 3 or 4.
