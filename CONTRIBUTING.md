# Contributing

## Proposing a change

1. Create a branch from the default branch.
2. Make the change.
3. Run the tests (see below).
4. Update the documentation that describes the changed code.
5. Open a pull request that states what the change does and how it was tested.

## Data and secrets

No real data is included in the repository, in any form.

- No patient-level records, and no extracts or samples of them.
- No real identifiers or other real values in code, comments, tests or documentation. Formats are illustrated with made-up placeholders such as `XXXX-0001`, and file names with made-up examples such as `zim_admissions_2026-01-31.csv`.
- No figures taken from real data: row counts, percentages or results of a run.
- No passwords, tokens or other credentials.

Test input is generated by the test scripts from the dictionaries. `cleaning_pipeline_R/input/` and `cleaning_pipeline_R/output/` are excluded from version control. Check the staged changes before each commit (`git diff --cached`).

## Tests

From `cleaning_pipeline_R/`:

```
Rscript tests/test_input_naming.r
Rscript tests/test_pii_guard.r
```

Each script exits with status 0 when every check passes and 1 otherwise. Both run in a temporary copy of the pipeline on synthetic input and do not read or write `input/` or `output/`.

A change to the removal of personal data or to the guard `assert_pii_removed()` is covered by a check in `tests/test_pii_guard.r`. A change to file-name parsing or to the value parsers is covered by a check in `tests/test_input_naming.r`.

A change to a constant of `00_build_dictionary/00_build_dictionary.r` is followed by a rebuild of the dictionaries and a run of `00_build_dictionary/validate_dictionaries.r`.

## Documentation

The documentation describes what the code does, and nothing else.

- A change to a module is described in the `README.md` of that module. A change to a setting, an input or an output is also described in `cleaning_pipeline_R/readme.md` and `cleaning_pipeline_R/how_to_run.md`.
- `MANUAL.txt` holds the documentation files in one document and is updated when one of them changes.
- No history in the documentation: no earlier behaviour, no description of fixes, no dates, no names of people. Releases are recorded in `CHANGELOG.md`.
- Column names, function names, setting names and file names are written exactly as in the code.
- UK English. The project name is "Neotree".

## Code style

- R scripts use `snake_case` for objects and two-space indentation, as in the existing modules.
- ASCII characters only in code.
- Paths are relative to the pipeline folder or set through a setting. No machine-specific absolute paths.
- Comments describe what the code does and carry no names, dates or change history.
- A change to the set of packages is made in both `install_packages.r` and `required_packages.txt`.
