# Module 01: Standardise Column Headers

## Purpose
Normalises every column name in the raw CSV to a consistent lowercase format with no whitespace, no underscores, and clean dot separators. Also removes `.parentKey` app-navigation columns that carry no clinical data.

---

## When It Runs
First data-processing step -- runs immediately after Module 00 (setup) and Module 00a (PII removal). All subsequent modules depend on the normalised names produced here.

---

## Logic

### Normalisation rules (applied to every column name)

| Rule | Example before | Example after |
|------|----------------|---------------|
| Strip leading/trailing whitespace | `" Baby Cry "` | `"Baby Cry"` |
| Normalise spaces around dots | `"Baby Cry . Value"` | `"Baby Cry.Value"` |
| Collapse multiple spaces | `"Baby  Cry"` | `"Baby Cry"` |
| Remove all remaining spaces | `"Baby Cry.Value"` | `"BabyCry.Value"` |
| Remove underscores | `"unique_key"` | `"uniquekey"` |
| Lowercase | `"BabyCry.Value"` | `"babycry.value"` |

This produces compact, consistent names such as `babycry.value`, `datetimeadmission.value`, `uniquekey`, and `facility` that all downstream modules rely on for exact-match lookups.

### Columns dropped

1. **`.parentKey` columns** -- app-navigation metadata generated by the Neotree app (e.g. `babycryptriage.parentkey`). These are hierarchy/parent-form reference fields with no clinical or analytical value. Present in admissions and discharges exports.

Previously, `scriptid`, `script_version`, `scriptversion`, `transformed`, and related columns were also dropped here. They are now **retained** because they carry useful session-level provenance (form version, transformation status). They survive as bare columns and are passed through to the final output by Module 15's bare-column passthrough. See Module 15 README for details.

### Columns renamed to avoid a reserved-column collision

A raw data field whose name normalises to `facility`, `uid`, or `uniquekey` (the reserved system key columns) would otherwise silently lose to that system column later in the pipeline: Module 07's duplicate-column logic groups columns by name and always keeps whichever twin has more non-missing data, and the always-populated system column wins every time -- discarding the genuine clinical field with no warning.

Immediately after name normalisation, any raw column listed in `cfg$reserved_column_renames` (set per-dataset in `00_setup.r`) is renamed to a non-colliding name before Module 07 ever runs. For example, MWI `phc_discharges` renames its own `Facility.value`/`Facility.label` field -- distinct from the system `facility` column, and otherwise erased by it -- to `facilityname.value`/`facilityname.label`. The rename count is logged as "Reserved-collision renames" in the module report. `cfg$reserved_column_renames` is `NULL` for datasets with no known collision, so this step is a no-op everywhere else.

## Inputs

| Object | Description |
|--------|-------------|
| `df_raw` | Raw data frame from Module 00a (or loaded from `cfg$csv_filepath` if not already in environment) |

---

## Outputs

| Object / File | Description |
|---------------|-------------|
| `df` | Data frame with standardised column names and metadata columns removed |
| `reports/01_column_standardisation_report.txt` | Count of columns renamed and dropped (optional) |

---

## Key Function

**`clean_columns(df, report_filepath = NULL)`** -- applies all normalisation rules, drops `.parentKey` columns, returns the cleaned data frame.

---

## Notes

- Both supported data formats produce identical normalised column names: `BabyCryTriage.value` (database) and `Baby Cry Tria Ge. Value` (Metabase) both become `babycry.value`.
- The normalised names match the `raw_value_column` / `raw_label_column` values in the data dictionary, enabling dictionary lookups in Module 04.
